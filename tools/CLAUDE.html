CLAUDE.md

김호성 선생님의 2027학년도 LMS. 구글 클래스룸처럼 반(학급)을 1년 단위로 개설하는 구조다. 2026-10-25에 hoistory/lms2027/에서 독립 레포로 옮겼다(그 폴더의 커밋 5개는 이 레포 기록에 그대로 있다).

세션 시작 규칙

  • 매 세션 시작 시 git pull을 먼저 한다.
  • 그다음 LMS2027_작업기록.md를 읽는다. 컴퓨터를 옮겨 다니며 작업하므로 어디까지 했는지가 거기 있다.
  • 설계는 LMS2027.md, 선생님 말씀 받아쓰기는 LMS2027_요구사항.md.

Git 규칙

  • 수정 후 확인 없이 git add, commit, push까지 한다. 파괴적인 작업(reset --hard, force push, 브랜치 삭제)만 먼저 묻는다.
  • 커밋할 때마다 LMS2027_작업기록.md에 한 줄 이상 남긴다(선생님 지시 2026-10-23).

응답 규칙

  • 모든 대화, 주석, 화면 문구는 한국어.

시킨 것만 한다 (선생님 지시 2026-10-25)

  • 선생님이 말한 것만 만든다. 편해 보이는 기능, 기본값, 정해 둔 목록을 짐작해서 더하지 않는다.
  • 예: 과목을 "사회, 역사"로 미리 채워 둔 것: 선생님이 무엇을 가르칠지는 선생님만 안다. 빼라는 지시를 받았다
  • 필요해 보이는 것이 있으면 만들지 말고 끝에 한 줄로 묻는다.

배포

  • GitHub Pages(main 브랜치 루트). 주소 https://hoseong911.github.io/lms2027/. 빌드 없음, 바닐라 HTML/CSS/JS.
  • 캐시 무효화는 ?v=YYYYMMDDx를 손으로 올린다(index.html, admin.html의 css/js, js 안의 model.js import).

이식하면서 2027 구조에 맞춘 것(그대로 베끼지 않은 자리)

  • hoistory는 반이 학번에서 계산됐다(Math.floor((sid-30000)/100)). 2027은 강의실(courses)이 실체라 반 탭이 강의실 탭이다.
  • hoistory의 "미실시 체크박스"는 2027에서 그 강의에 그 칸이 있는가로 대신한다.
  • hoistory 진도표의 [번호 자동 채우기], [주제 새로고침]은 번호와 주제를 손으로 적어 맞춰 줘야 했기 때문에 있던 단추다. 2027은 번호가 꽂힌 순서에서 나오고 주제가 강의 제목 그 자체라 가져오지 않았다.
  • grade_publish_status/{강의}_{반}은 2027에서 꽂힌 강의가 이미 반 단위라 course_lessons.gradePublished 필드로 둔다.

더미 데이터 (tools/더미데이터.mjs, 2026-10-28)

"모든 메뉴가 다 채워졌다고 가정하고" 작업한다(선생님 지시). Firestore에 더미가 들어 있다.

  • node tools/더미데이터.mjs fill / clear. Firebase CLI 로그인(firebase login)이 돼 있어야 한다.
  • 새로 만든 제출물, 성적, 미션 앱에는 dummy: true가 있고 clear는 그것만 지운다.
  • model.js의 실제 함수로 만들므로 데이터 모양을 바꾸면(model.js) 도구도 같이 맞는지 본다.

hoistory와의 관계

  • Firebase 프로젝트는 같다(ho0911seong-56638). 선생님 계정, 기존 앱 데이터와 한 데이터베이스를 쓴다.
  • firestore.rules는 hoistory 레포에 있다. 규칙 파일은 프로젝트에 하나뿐이라 둘로 나눌 수 없다. 이 레포의 컬렉션 규칙은 hoistory/firestore.rules의 "2027 LMS" 구역에 쓰고, hoistory에서 ~/bin/firebase.exe deploy --only firestore:rules --project ho0911seong-56638로 배포한 뒤 hoistory에도 커밋한다.
  • shared/icons.js, shared/firebase-config.js는 hoistory에서 복사해 왔다. 이제 이 레포 것이 따로 간다. 아이콘을 더할 때는 이 레포의 shared/icons.js에 더한다.
  • pwa.js, sw.js도 이 레포 것이다. hoistory의 서비스워커는 스코프가 /hoistory/라 여기를 덮지 못한다.

학생 로그인

  • Firebase Auth를 쓰지 않는다(2026-10-23 선생님 결정). 학번, 이름, 본인이 정한 비밀번호의 일치 여부만 본다. 가짜 이메일, 익명 로그인, 커스텀 토큰 제안을 다시 꺼내지 말 것.
  • 로그인 화면은 2026 hoistory/lms/ 것을 그대로 옮겼다(선생님 지시).

Firestore와 Auth를 붙일 때 같이 할 것 (2026-10-29 선생님 승인)

지금은 일부러 미뤄 둔 것이다. 뼈대 단계라 안에 든 것이 다 더미이고, 코드만 고쳐도 보안 규칙이 없으면 막히는 것이 아니라 안 보이는 것뿐이기 때문이다. Firestore를 붙이는 그 작업에 묶어서 한다.

  • 학생 화면이 남의 성적과 피드백까지 내려받는다. index.js가 M.loadCore()를 부르고 (index.js:44) loadCore()는 course_grades와 course_submissions를 반 전체 것으로 통째로 받아 온다(model.js:240). 화면에는 본인 것만 그리지만 데이터는 이미 학생 브라우저에 들어가 있어 개발자 도구로 같은 반 점수, 교사 피드백, 남의 답변을 그대로 볼 수 있다.
  • 고치는 법은 둘을 같이 해야 한다. 하나, 학생 쪽은 본인 학번 것만 질의한다. 둘, hoistory/firestore.rules에서 남의 문서는 아예 내려보내지 않는다.
  • 학생에게 Auth 계정을 만들지 않기로 했으므로(위 "학생 로그인") 규칙에 "본인 것만"을 쓸 수 없다. 검증을 Cloud Function으로 옮기는 길이 남는다. LMS2027.md의 "Auth 없이 비밀번호를 지키는 길" 표에 있는 셋째 줄과 같은 작업에 묶인다.

코드 규칙

  • 인라인 onclick과 window 노출을 쓰지 않는다. data-act + 이벤트 위임.
  • 모듈 최상위 상태는 state 하나에 모은다.
  • 부트 가드 --lms-css-ok를 지우지 않는다. shared/theme.css에 있다(@import 체인의 끝). index.js, admin.js가 이 값을 보고 화면을 띄운다.
  • 브라우저 기본 대화상자(alert, confirm, prompt) 대신 어드민의 ask() 모달을 쓴다.
  • 컬렉션 이름에 연도를 넣지 않는다. 연도는 필드로만.

화면 규칙 (선생님 지시)

작은 글씨 설명 금지 (2026-10-25, 2026-10-27 보강)

  • 메뉴, 제목, 입력 칸, 버튼 밑이나 옆에 작은 글씨로 주석처럼 붙는 설명문을 만들지 않는다. 선생님이 싫어한다.
  • 예: 페이지 제목 밑의 "반을 고르면 그 반의 메뉴들이 나옵니다", 입력 칸 밑의 "A열 학번, B열 이름" 같은 것
  • 부가설명은 시킬 때만 단다 (2026-10-27). 목록 항목 옆의 개수 요약("학생 N명", "개설 강의 N개")도 기본으로 넣지 않는다. 선생님이 달라고 한 자리에만 넣는다.
  • 남겨도 되는 것: 방금 한 일의 결과나 오류 메시지, 빈 목록 표시
  • 빈 목록 표시도 짧게. "없다"까지만 쓰고 "위에서 ~해 보세요" 같은 안내는 붙이지 않는다

입력 칸 위에 이름표를 달지 않는다 (2026-10-25)

  • 입력 칸 위에 "학년도", "학년" 같은 작은 이름표를 달지 않는다.
  • 숫자의 단위는 칸 오른쪽에 보통 크기 글씨로 붙인다(2027 학년도, 2 학년, 3 반). 값이 채워져 있어도 무슨 칸인지 보이게.

플레이스홀더도 시킬 때만 (2026-10-27)

  • 입력 칸 placeholder를 기본으로 넣지 않는다. 선생님이 "웬만하면 안 쓰고 원할 때만"이라 했다.
  • 무슨 칸인지는 곁의 단위 글씨나 값이 이미 채워진 수정 폼, 또는 (모달처럼 꼭 필요한 곳의) 필드 이름표로 알린다. 형식 안내가 꼭 필요하면 칸마다 placeholder로 반복하지 말고 표/구역 위에 한 줄로 둔다.

숫자 칸에 스크롤 화살표를 두지 않는다 (2026-10-25)

  • 모든 숫자 입력 칸에 위아래 스크롤 화살표(스피너)를 없앤다. 작업마다 예외 없음.
  • type="number"를 쓰지 않고 type="text" inputmode="numeric"으로 만든다(폰에서는 숫자 키패드가 그대로 뜬다). 값은 읽을 때 숫자로 바꾼다.
  • 혹시 type="number"가 섞여도 화살표가 안 보이게 admin.css 맨 아래에 전역 규칙이 있다. 지우지 말 것.

체크로 무엇을 빼는 곳은 체크박스만 눌리고, 해제는 확인 창 (선생님 지시 2026-10-29)

  • 강의실 등록처럼 체크를 풀면 무엇이 빠지는 곳은 줄을 <label>로 감싸지 않는다. 줄이나 글자를 눌러 체크가 바뀌면 모르고 빼게 된다(실제로 학생이 빠졌다). 체크박스를 눌러야만 바뀐다.
  • 해제할 때는 확인 창(confirmDelete)을 띄우고, 확인 전까지 체크를 되돌려 둔다. 체크해서 넣는 쪽은 바로 한다.

되돌릴 수 없는 큰 삭제는 관리자 계정으로 다시 인증 (2026-10-25)

  • 학년도 삭제는 이름 입력 대신 관리자 이메일과 비밀번호로 Firebase 재인증(reauthenticateWithCredential)을 통과해야 한다. 선생님이 "너무 허술하다"고 했다.
  • 반 하나 삭제는 반 이름을 그대로 입력하는 확인으로 둔다.

버튼, 배지, 태그, 카테고리 모양 (2026-10-25, 같은 날 한 번 정정됨)

  • 알약 모양(border-radius:999px) 테두리를 쓰지 않는다.
  • 테두리는 진짜 액션 버튼(추가, 수정, 삭제, 확인, 취소, 비밀번호 초기화 같은 아이콘 버튼 .ib)에만 둔다. 모서리는 8px.
  • 배지(학생이 든 강의실 표시 .stu-course, 아카이브 표시 .badge)는 테두리 없는 배경색.
  • 태그와 카테고리(과목, 학년, 반 거르기 .tag, 학년도 고르기와 반별, 메뉴별 관리의 고르기 .pick)는 테두리와 배경 없이 글자만 두고 줄 아래에 얇은 구분선을 긋는다. 켜진 것은 진한 글씨에 그 아래 굵은 선(쇼핑몰 카테고리 줄 모양). 배경색은 쓰지 않는다.

  • 처음엔 "태그는 배경, 카테고리는 세로 구분선"으로 정했다가 선생님이 바로 정정했다. 세로 구분선도 쓰지 않는다.

높이, 배경, 강조색 (선생님 지시 2026-10-29)

  • 높이는 두 값만: 조작 칸(입력 칸, 드롭다운, 아이콘 단추, 작은 버튼, 토글, 검색 칸) --h-ctl 32px, 목록 줄 --h-row 46px. shared/theme.css에 있다. 줄 안에 무엇이 들었든 줄 높이는 같다. 새 화면에서 px로 높이를 따로 주지 않는다.
  • 흰 카드 배경을 쓰지 않는다. 줄, 상세, 카드, 입력 칸, 버튼 전부 바탕이 비치고 선으로만 나눈다. 흰 바탕은 모달과 로그인 창만(덮개 위에 떠야 하므로).
  • 목록 줄은 가로 구분선만. 테두리를 위아래에만 두고 좌우에는 두지 않는다. 좌우 선이 없으니 모서리를 둥글릴 자리도 없어 radius를 주지 않는다. 맞닿는 줄의 테두리는 하나로 합친다(+ 셀렉터로 border-top:0). .row, .partrow, .selrow, .checkline이 다 이 모양이다.

  • 적용 범위는 어드민과 학생 화면 둘 다다 (선생님 지시 2026-10-29 "싹다 맞춰봐").
  • 묶음 패널로 보는 것(바탕 없이 선만): .pane, .detail, .score-detail, .gradebar, .formrow, 학생 화면의 .score, .partview.
  • 합쳐진 목록 줄로 보는 것: .row, .partrow, .selrow, .checkline, .qcard(.qcards의 gap은 0), .pchip.
  • 고른 것을 반투명 레드로 알리는 것: 위 목록 줄들과 .seg-b.on, .qcard.open/.on, .pchip.has.

  • 미채점은 판정이 아니라 아직 안 본 것이라 회색(.gnote.muted)으로 둔다.
  • 표도 가로 구분선만. 세로 테두리, 바깥 테두리, 칸 배경색 없음. 표 안 입력 칸은 평소엔 테두리 없이 글자만.

  • 자리를 맞춰야 하는 숫자(.mono, 학번 같은 것)도 글꼴은 Pretendard를 쓴다. 고정폭 글꼴로 바꾸지 않는다. 자리 맞춤은 font-variant-numeric:tabular-nums로 한다(선생님 지시 2026-10-29).
  • 같은 일을 하는 단추를 한 화면에 둘 두지 않는다. 예: 비밀번호 초기화는 줄(좁은 화면)과 상세 머리줄(넓은 화면)의 아이콘 단추 하나로 끝낸다. 상세 안에 같은 단추를 또 두지 않는다(선생님 지시 2026-10-29).
  • 넓은 화면(1100px 이상)은 왼쪽 목록 + 오른쪽 상세 두 칸, 좁으면 줄 아래로 펼친다(admin.js의 WIDE, CSS .split). 강의실 관리(--w-list-room 170px), 학생 관리(--w-list 300px), 미션 활동, 오늘의 질문 질문 관리, 형성평가, 성적 조회가 전부 이 틀이다. 새 목록 화면도 이 틀로 만든다.

  • 성적 조회만 거꾸로다(선생님 지시 2026-10-29): 왼쪽이 표라 왼쪽이 넓고 오른쪽 내역이 --w-sc-detail 230px로 좁다. 오른쪽에는 강의 차수만 적고 강의 제목은 뺀다. 영역 셋의 달성, 기한 OX를 한 줄에 하나씩 세로로 쌓는다.

스크롤바는 가늘고 연하게, 화살표 없이 (선생님 지시 2026-10-29)

가운뎃점, 줄표, 화살표를 쓰지 않는다 (2026-10-25, 2026-10-28 전면 확대)

  • 가운뎃점(·)과 줄표(—, –)는 내가 쓰는 모든 글에서 쓰지 않는다 (2026-10-28). 화면 문구만이 아니라 코드 주석, 레포 문서(.md), 커밋 메시지, 선생님께 드리는 답변까지 전부다.
  • 항목을 잇던 가운뎃점은 쉼표, 조사, 괄호, 공백으로 쓴다.
  • 설명을 붙이던 줄표는 쌍점(:), 마침표, 괄호로 쓴다.
  • 2026-10-25에는 코드 주석을 예외로 뒀는데, 2026-10-28에 선생님이 예외 없이 걷어내라고 했다.
  • 화면 문구에서 화살표(→, ←, ➡ 등)로 잇지 않는다. "반 관리 → 학급 관리" 같은 표기 금지.
  • 기호 자체가 자료인 자리만 예외다. 글머리 기호를 가려내는 정규식(slide-render.js의 BULLET_RE)과 그 기호를 설명하는 주석처럼, 글자를 바꾸면 뜻이 사라지는 곳.

화면 문구는 경어(~습니다체)로 쓴다 (선생님 지시 2026-10-28, 같은 날 바로 정정됨)

  • 한 차례 "~다체로 쓰라"는 지시가 있었는데, 무뚝뚝하게 들려 선생님이 바로 정정했다. 싸가지 없이 들리라고 한 게 아니라 경어를 쓰라는 뜻이었다. 그러니 화면에 나오는 모든 글은 ~습니다체(경어)로 쓴다. TEXT_FIELDS의 기본값, 빈 목록 표시, 오류 문구, 토스트, 확인 모달 전부 해당한다.
  • "강의실이 없다." → "학번에 해당하는 강의실이 개설되지 않았습니다."
  • "비밀번호가 비었다." → "비밀번호를 입력하시길 바랍니다."
  • "삭제했다." → "삭제했습니다."
  • 로그인 화면과 오류 문구는 선생님이 일반 설정에 직접 입력해 두었던 문구를 그대로 코드에 옮겨 적었다(2026-10-29, index.js).
  • 2026-10-28에 ~다체로 한 차례 바뀐 곳이 TEXT_FIELDS 밖에도(어드민 토스트, model.js 오류 메시지, 미니앱 템플릿 등) 레포 전체에 걸쳐 있었다. 같은 날 전부 경어로 되돌렸다. 가운뎃점, 줄표를 뺀 punctuation 규칙은 그대로 살려 뒀다(말투만 되돌리고 그 규칙은 안 건드림). AI에게 보내는 프롬프트 문자열(concept-note.js의 CE_LESSON_JSON_INSTRUCTION)과 코드 주석은 "화면 문구"가 아니므로 이 규칙 대상이 아니다.

한 묶음은 카드 하나로 담는다 (선생님 지시 2026-10-28)

  • 항목마다 카드를 따로 만들지 않는다. 같은 소제목 아래 줄이 여럿이면 그 묶음 전체가 카드 하나고, 줄과 줄 사이는 얇은 선으로만 나눈다. 선생님이 "굳이 이렇게 일일이 나눌 필요가 있나 싶다"고 했다(일반 설정 화면을 보시고).

  • 새 목록 화면을 만들 때 줄마다 margin-bottom을 주어 카드를 떼어 놓지 말 것.

소제목은 본문보다 확실히 크게 (선생님 지시 2026-10-28)

일반 설정에서 바꾸는 것은 일반 묶음과 어드민 메뉴뿐 (2026-10-28, 2026-10-29 정정)

  • 2026-10-28에는 "모든 문구를 관리자가 바꿀 수 있게"였는데, 2026-10-29에 선생님이 정정했다: "오류문구는 그냥 하드코딩 해도 될거 같고, 다른 문구들도 하드코딩 해. 여기서 살릴거든 일반설정-일반, 어드민 메뉴만."
  • 그래서 화면 문구(로그인 화면 제목, 안내문, 버튼, 오류 메시지)는 코드에 바로 적는다. 새로 TEXT_FIELDS에 올리지 않는다.
  • 일반 설정에 남는 것: TEXT_FIELDS의 일반 묶음(브라우저 탭 제목, 사이트 이름, 어드민 이름, 오픈카톡 링크, 홈 화면에 추가 링크)과 어드민 메뉴(이름, 순서, 구분선). 화면은 이 값들을 M.getText(key)로 읽는다.
  • 일반 설정 화면은 두 단이다(왼쪽 일반, 오른쪽 어드민 메뉴, .gen-cols). 한 줄로 길게 늘어놓지 않는다(선생님 지시 2026-10-29: 휑하다).
  • 어드민 메뉴 이름과 순서, 구분선 자리도 일반 설정에서 정한다 (2026-10-29). 메뉴 이름은 M.menuName(key)로 읽고(화면 제목 <h2>도 같다), 왼쪽 메뉴는 M.adminMenus()로 그린다. ADMIN_MENUS를 직접 돌며 그리지 않는다. 구분선은 순서 배열(settings/general의 menuOrder) 안의 MENU_SEP 한 칸이다. 왼쪽 메뉴 맨 위 글자는 adminName.

아이콘은 SVG만, 액션 버튼은 아이콘으로 (2026-10-25)

  • 유니코드 이모지를 쓰지 않는다. 아이콘은 전부 shared/icons.js의 icon() SVG로.
  • 설명이 필요 없는 액션 버튼은 글자 없이 SVG 아이콘만 쓴다: 추가(plus), 수정(pencil), 삭제(trash-2), 저장(check), 취소(x), 업로드(upload), 명단(users), 아카이브(archive), 되돌리기(archive-restore), 로그아웃(log-out).
  • 아이콘 버튼에는 title과 aria-label을 단다(마우스를 올리면 뜨는 이름이라 작은 글씨 설명에 해당하지 않는다).
  • 무엇을 하는지 아이콘만으로 모호한 버튼은 글자를 쓴다.

조직 원리 (2026-10-26 제로베이스 재설계)

강의실은 "강의(차시)"와 "복습"을 담고, 강의 하나는 개념 노트, 미션 활동, 오늘의 질문, 형성평가 네 칸을 각각 있거나 없거나로 채운다. 콘텐츠 메뉴를 코드에 못박지 않는다. 자세한 건 LMS2027_요구사항.md의 68~78, LMS2027.md 7, model.js 머리 주석.

  • 강의 안 칸(각 강의에 최대 1개, 순서 자유): concept 개념 노트, mission 미션 활동, question 오늘의 질문, formative 형성평가(성적 무관). 사료, 사진, 영상은 개념 노트 안의 내용
  • 독립 메뉴: review 복습(성적 무관)
  • 포트폴리오 성적 = 개념 노트(수기, 교사 입력) + 미션 활동(참여 여부) + 오늘의 질문(AI 1차+교사). 형성평가, 복습은 빠진다

성적을 매기는 방식 (2026-10-28, hoistory/lms 성적 Check 틀 이식)

선생님 지시로 2026 lms에서 돌려 본 방식을 그대로 가져왔다. 점수를 강의마다 직접 적지 않는다.

  1. 강의마다 학생마다 영역(개념 노트, 미션 활동, 오늘의 질문)별로 달성 칸과 기한 칸을 체크한다. 영역마다 칸 하나씩이다. 배수(1배, 2배) 고르개는 선생님 지시로 걷어냈다(2026-10-28). lessons.parts.<칸>.weight 필드는 더 읽지 않는다
  2. 달성률 = 켜진 칸 / 가능한 칸. 성적 설정의 반영 강의 목록에 들고 그 반에 반영하기를 누른 강의만 센다
  3. 급간 표(settings/grade의 bands)에서 그 달성률에 맞는 줄을 찾아 영역 점수를 읽는다. 기본값은 개념 30, 미션 40, 질문 30으로 100점
  4. 세 영역 점수의 합이 포트폴리오 성적. 계산은 model.js studentGrade 한 곳에서만 한다
  • 칸이 없는 영역은 미실시다(0점, 달성률도 안 센다). hoistory는 칸 개념이 없어 미실시 체크박스를 따로 뒀지만 2027은 "그 강의에 그 칸이 있는가"가 그대로 답이다.
  • 성적 입력 표에는 영역 셋이 늘 다 선다(선생님 지시 2026-10-28). 그 강의에 미션 활동이 없어도 칸이 보이고, 영역 제목 옆 스위치로 켜고 끈다(setPartEnabled). 끄면 적어 둔 내용은 lessons.partsOff에 맡겨 두었다가 다시 켜면 되살린다. 오늘의 질문 관리의 스위치와 같은 길이다.
  • 머리줄의 달성, 기한 옆 체크표시를 누르면 그 열의 모든 학생이 한 번에 체크된다(setGradeColAll). 결석 학생은 건너뛴다.
  • 피드백 템플릿: 성적 설정에서 한 줄에 하나씩 적고(settings/grade의 feedbackTemplates), 성적 입력의 피드백 칸 옆 고르개에서 고르면 그 글이 칸에 들어간다.
  • 손으로 쓰기와 자동 끌어오기를 둘 다 둔다(선생님 지시).
  • 자동: 미션 활동과 오늘의 질문은 course_submissions에서 달성과 기한을 계산한다(autoDetect). 기한은 진도 관리에서 넣은 수업일자(course_lessons.date)와 제출 시각을 견준다. 진도 관리와 성적이 여기서 맞물린다. 오늘의 질문 판정은 hoistory thinkVerdict를 옮긴 것(50자 미만은 미달성, 지연 제출은 기한만 깎임)
  • 손: 교사가 누른 칸은 manual로 표시돼 다시 끌어와도 덮이지 않는다. 개념 노트는 LMS 밖 활동지라 늘 손으로만 넣는다
  • 이름을 누르면 결석(전부 미달성 고정)
  • 어드민 성적 메뉴는 hoistory와 같이 서브 메뉴 셋이다: 입력 / 설정 / 조회. 셋 다 과목 아래에서 움직인다(성적 설정의 반영 강의 목록도 과목별이다, 선생님 지시 2026-10-28).
  • 고르개는 한 줄이다(선생님 지시 2026-10-29): 과목은 머리줄 학년도 옆 드롭다운, 반은 카테고리 줄, 입력/설정/조회는 그 줄 오른쪽 끝 토글. 줄을 다시 셋으로 쌓지 않는다.
  • 기록은 course_grades(문서 id 꽂힌강의id_학번). 집계 컬렉션 course_scores는 쓰지 않는다.

컬렉션 이름 규칙

뿌리_세부 snake_case. 연도, 차수, 버전 금지(연도는 필드). 강의실에 매인 것은 전부 course_ 접두, 재사용 창고는 접두 없는 복수형, 파생은 뿌리를 물려받아 _로(예: mission_apps, grading_archive).
