2027 LMS 개편: 요구사항

선생님이 말씀하신 것을 모아 두는 곳. 2026-10-27, 선생님 지시로 날짜순에서 주제별로 다시 묶었다. 번호와 날짜는 원래 것을 그대로 달았으므로 (31, 10-25)는 "31번 항목, 2026-10-25에 말씀하신 것"이다. 맨 아래 번호순 찾아보기로 1번부터 되짚을 수 있다.

지금 설계의 기준은 2. 조직 원리다. 2026-10-26에 제로베이스로 다시 세운 것이라, 그 앞의 항목과 어긋나면 조직 원리 쪽이 이긴다. 새 말씀은 해당 주제 칸 맨 아래에 번호를 이어서 덧붙인다.

1. 큰 방향

  • 구글 클래스룸 스타일로 간다. 연도가 바뀌든 학년이 바뀌든 반이 생기고 없어지든 영구적으로 쓸 수 있는 시스템. (1, 10-23)
  • 그러면서 지금 쓰는 방식은 유지한다: 강의 생성, 학생 일괄 업로드 같은 것. (2, 10-23)
  • 이 두 축을 기준으로 만든다. (3, 10-23)
  • 일단 큰 틀부터 만든다. (9, 10-23)
  • 시키는 것 말고 다른 것은 하지 않는다. (24, 10-25)
  • 어드민을 하나씩 뜯어 고쳐 나간다. (16, 10-25)

여섯 용도 (선생님이 적은 전체 용도) (69, 10-26)

  1. 강의(PPT 역할): 교사가 교실 화면에 투사하는 것이 주, 학생 모바일 복습이 보조. 활동지(글, 사료 위주)를 올리면 HTML 슬라이드로. 제작 효율이 최우선
  2. 미니 웹앱: 활동과 공유가 한 몸. 슬라이드를 빠져나가지 않고 학생 실시간 제출을 그 자리에서 공유
  3. 활동 취합, AI 채점, 아카이빙: 포트폴리오 수행평가가 핵심
  4. 성적 창구: 학생이 항목별과 최종을 실시간 확인
  5. 애플리케이션화: 홈 화면 앱처럼, 경험치와 포인트와 뽑기 유지, 추가 흥미 요소는 열어 둠
  6. 복습 허브: 자동 생성과 외부 제작을 모두, 순수 복습(성적 무관)

운영 틀 (74, 10-26)

구글 클래스룸처럼 영구히 쓴다. 학생이 로그인 → 강의실 선택 → 그 안의 활동에 참여. 역사뿐 아니라 담당하는 어떤 과목이든 강의실을 연다.

2. 조직 원리 (지금 설계의 기준)

2026-10-26, "필요한 것 위주로 중구난방이라 아예 제로베이스부터 다시"라는 지시로 데이터 모델과 개념까지 백지에서 다시 세웠다. 1~67은 재료로 남기고 기준은 여기다.

강의실은 "강의(차시)"와 "복습"을 담고, 강의 하나는 개념노트, 미션, 질문노트, 형성평가 네 칸을 각각 있거나 없거나로 채운다. 콘텐츠 메뉴를 코드에 못박지 않는다. (68, 10-26)

강의 안 네 칸 (71, 10-26)

개념노트, 미션, 질문노트, 형성평가. 각 종류는 한 강의에 최대 1개, 있거나 없거나. 순서는 선생님이 자유롭게 바꾼다. 사료, 사진, 영상은 별도 칸이 아니라 개념노트 안의 내용. 형성평가는 성적에 반영하지 않는다.

복습은 독립 메뉴 (72, 10-26)

강의와 별개로 선다. 자동 생성 퀴즈와 외부 제작 문제를 모두 담는다. 성적 무관.

학생이 강의실 안에서 쓰는 세 배치 (85, 90, 10-27)

앞의 둘은 둘 다 만든다. 둘 다 필요하다.

  1. 강의 보기: 1강, 2강, 3강을 고르면 그 강의가 쭉 이어져서 보인다
  2. 메뉴: 개념노트 따로, 미션 따로, 질문노트 따로, 형성평가 따로, 복습 따로, 성적 따로. 2026 hoistory lms의 메뉴와 같은 방식이다
  3. 콘텐츠: 뽑기나 게임 같은 것이 나중에 들어갈 자리. 지금은 비워 둔다

처음에 "강의별, 메뉴별"로 달았다가 선생님이 "강의 보기, 메뉴"로 고치고 셋째로 "콘텐츠"를 더하라고 하셨다.

2026-10-30에 바뀌었다 (108, 111). "콘텐츠에 들어갈 내용들은 전부 강의실 선택 시 선택할 수 있게 뺄거야. 그러니까 강의실 내 메뉴에서는 빼줘. 그리고 강의 보기도 하나의 메뉴로 설정할거야." 이제 강의실 안은 탭 없이 메뉴 한 화면이다.

9. 성적, 공유, 아카이브

포트폴리오 수행평가 세 요소 (70, 10-26)

  1. 개념노트: 활동지에 수기로 작성. LMS 밖이고 교사가 점수만 수기 입력
  2. 미션: 잘하고 못하고보다 참여, 수행 여부 우선
  3. 질문노트: 수업 중 제시한 질문에 대한 본인 답변

②와 ③만 LMS에서 취합하고 AI가 1차 채점한다. 형성평가와 복습은 성적에서 빠진다.

성적 메뉴 (97, 10-28)

"성적 메뉴 만들어보자." 첫 화면 모양과 개념노트 입력 단위를 여쭤 고르신 것:

  • 첫 화면은 강의실 한 판 표. 과목 탭에서 반 탭으로 강의실을 좁히면 그 반 학생 전원이 세로로, 포트폴리오 세 항목과 합계가 가로로 놓인다.
  • 개념노트 점수는 강의(차시)마다 입력한다. 학생 줄을 누르면 차시별로 펼쳐진다. "어느 차시를 안 걷었는지 보인다"는 쪽을 고르셨다.
  • (97 갱신, 같은 날 99로) 같은 날 "lms 기본 틀을 이식하라"는 지시가 와서 점수를 차시마다 직접 적는 방식은 달성과 기한 체크 + 급간 환산으로 바뀌었다. 고르신 모양 가운데 강의실 한 판 표는 성적 조회 화면으로, 차시마다 교사가 넣는다는 뜻은 성적 입력 화면(강의를 고르고 그 반 학생을 체크)으로 살아 있다.

성적은 손으로도 쓰고 자동으로도 끌어온다 (98, 10-28)

"성적은 내가 손으로 쓸 수도 있어야 하고, 파이어베이스에서 자동으로 끌고 오는 것도 있어야 해."

  • 미션과 질문노트는 제출물에서 자동으로 달성과 기한을 끌어온다.
  • 선생님이 누른 칸은 손으로 정한 것으로 표시되고, 다시 끌어와도 덮이지 않는다.
  • 개념노트는 LMS 밖 활동지라 늘 손으로만 넣는다.

lms의 기본 틀을 이식한다 (99, 10-28)

"일단 미션 활동이랑 오늘의 질문, 성적 전부 다 hoistory/lms에서 기본 틀을 이식해 줘." "한마디로 1번 2번 둘 다 lms에서 기본 틀 이식해 오는 거야." (1번은 진도 관리: 96) 가져온 목록과 2027 구조에 맞춰 바꾼 자리는 CLAUDE.md의 "hoistory/lms에서 이식한 것" 표에 있다. 성적 계산 방식(달성률을 급간 표로 환산)도 2026 lms 것을 그대로 쓴다.

교사는 PC와 모바일 둘로, 학생은 폰과 패드 등 모바일로 들어온다. PC 전용 화면을 만들지 말고 모바일과 PC에 함께 적용되는 UI 한 벌로 간다.

묶음과 카드 (91, 10-28)

  • 항목마다 카드를 따로 두지 않는다. 큰 항목(묶음) 하나가 카드 하나다. "굳이 이렇게 일일이 나눌 필요가 있나 싶다." 일반 설정 화면을 보시고 하신 말씀이고, 디자인 규칙으로 잡으라고 하셨다.

글자

  • 작은 글씨로 주석처럼 설명해 주는 것은 만들지 않는다. 개인적으로 싫다. (17, 10-25)
  • 묶음 소제목을 더 키운다. "일반", "학생 로그인 화면" 같은 부제목이 너무 작게 보인다. (92, 10-28) → --fs-head(18px) 본문색으로 올렸다.
  • 가운뎃점과 대시는 어디에도 쓰지 않는다. 화면 문구만이 아니라 내가 글을 쓰는 모든 자리 (코드 주석, 레포 문서, 커밋 메시지, 답변)에서 쓰지 않는다. 있는 것도 싹 걷어냈다. (94, 10-28)
  • 화살표 연결 금지. (17, 10-25)
  • 모든 기본 문구는 ~다체. ~요체(~습니다, ~하세요, ~해 주세요)를 쓰지 않는다. (95, 10-28)
  • (95 정정, 같은 날) 바꿔 놓은 것을 보시고 "싸가지 없이 하라는 게 아니라 경어를 쓰라는 뜻" 이라고 바로잡으셨다. 화면에 나오는 모든 글은 ~습니다체(경어)다. 레포 184곳을 되돌렸다. 가운뎃점과 대시를 뺀 규칙(94)은 그대로 살아 있다.
  • 입력 칸 위의 작은 이름표는 필요 없다. 헷갈릴까 봐 적은 거면 "학년도 (숫자 입력)"처럼 칸 안에. (18, 10-25)

입력

  • 숫자 칸 옆 스크롤 화살표(스피너)를 없앤다. 모든 작업에 동일하게 규칙으로. (18, 20, 10-25)

버튼, 배지, 태그

  • 알약 모양 테두리 버튼은 규칙으로 없앤다. 테두리는 진짜 액션 버튼에만. (38, 10-25)

  1. "콘텐츠에서 활동지 올리는 기능이 없네? 확인 좀 부탁해" → 확인 결과 활동지 올리기는 강의 라이브러리의 강의 편집 탭에만 있었다. 콘텐츠 탭 머리줄에도 뒀다. 단추 둘이 같은 길을 부른다.
  2. "콘텐츠 내에서 번호를 표시하든 페이지를 표시하든 숫자가 있잖아 그거 하나로 통일 좀할게." → 전에 셋이었다(문항 번호는 네이비 바탕 흰 숫자 배지, 페이지 번호와 줄 번호는 네이비 글씨). 셋 중 둘이 쓰던 네이비 굵은 글씨 숫자로 맞췄다(.axnum. 플랫, 미니멀 기조).
  3. "전시 학습 확인에서 ox를 진위형으로 바꿔주고, 그 문항 유형 고르는 드롭다운 여백이 너무 없어(위아래)" → 유형 이름을 형성평가와 하나로 맞췄다(ox = 진위형). 전에는 전시학습확인만 "OX"였다. 드롭다운은 select.f에 조작 칸 높이(--h-ctl 32px)를 줬다. 전에는 브라우저 기본 높이였다.
  4. "개념 노트 페이지에서는 페이지 추가하는 버튼을 위로 올려줘. 저장버튼도 위로 올려주고" → 페이지 추가를 편집창 맨 위로 올렸다. 저장 단추는 없었어서 새로 만들어 머리줄에 뒀다 (칸은 전부터 커서가 빠질 때 저장된다. 이 단추는 눌러서 확인을 받는 자리다).
  5. "행 추가하는 버튼은 페이지 제목란을 줄이고 순서바꾸는 버튼 다음에 추가버튼을 위치시켜줘" → 머리줄이 번호, 제목 칸, 단추 넷(위, 아래, 묶음 추가, 삭제) 순이 됐다. 제목 칸은 폭을 정했다.
  6. "행라벨과 내용은 가로로 쌓지 말고 세로로 쌓아줘. 그리고 라벨 내용 이라는 문구는 없애고 그걸 플레이스홀더로 잡아줘." → 라벨이 위, 내용이 아래다. 안내 글줄은 걷고 칸 안 플레이스홀더로.
  7. "라벨 내용 부분은 시작하는 위치를 페이지 숫자랑 같은 위치에서 시작하게 해줘" → 왼쪽 들여쓰기를 걷었다. 라벨과 내용이 페이지 번호와 같은 선에서 시작한다.
  8. "폰트를 하나 더 사용하자. 페이퍼로지 폰트야. 그건 개념 노트에서만 사용할게 일단 알고만 있어 내가 어디서 사용할지는 따로 말해줄게" → 글꼴을 받아 두고 --font-note로 이름만 달았다. 아직 어느 칸에도 걸지 않았다. 쓸 자리는 선생님이 따로 말씀하실 자리다.

개념 노트 어드민 둘째 손질 (133, 10-30)

  1. "올린 활동지를 삭제하는 기능은 없네 그거 추가해줘." → 활동지 올리기 옆에 지우기를 뒀다. 활동지 파일은 저장하지 않으므로(브라우저에서 글자만 꺼내 쓴다) 지울 파일이 없다. 그래서 그 내용으로 채운 페이지를 비우는 것이 지우기다. 올리기가 개념 노트와 미션 활동 둘을 채우니 지우기도 둘을 같이 본다. 몇 페이지를 지우는지 세어 보여 주고 묻는다.
  2. "저장 미리보기 활동지 올리기 이렇게 문구를 넣은 버튼 말고 그냥 svg 이모지만 써서 버튼 만들어줘. 그리고 버튼이 다 빨간색인 이유가 있을까?" → 글씨를 떼고 아이콘 단추(.ib)로 바꿨다. 빨간색이던 까닭: 미리보기가 쓰던 레드 채운 단추 클래스(.btn-text, 주 버튼용)를 단추를 늘릴 때 그대로 가져다 쓴 탓이고 뜻이 있던 것이 아니다. 지금은 화면 규칙대로 주 동작(저장)만 레드, 되돌릴 수 없는 것(지우기)만 레드 테두리, 나머지는 회색이다.
  3. "개념 노트부분에서 스크롤이 생기면 헤더부분은 고정이 되어야 하는데 안되네 이거 고정되어야 해 규칙으로도 박아줘" → 축 편집기 머리줄, 단계 줄자, 단계 이름 줄을 position:sticky로 붙였다. 규칙은 "11 화면 규칙"의 스크롤이 생기면 머리줄은 고정한다에 적었다.

활동지 지우기는 강의 내용 전부를 비운다 (134, 10-30)

  • "활동지를 지웠는데 왜 강의는 그대로지? 강의 콘텐츠도 없어저야지. 콘텐츠에서 지우는 건 변형되서 올라온 콘텐츠 자체를 지우는거잖아." → 까닭: 133에서 개념 노트와 미션 활동 페이지만 비우도록 범위를 좁게 잡았다. 그래서 표지, 전시학습확인, 학습 목표, 동기 유발, 맺음말 다섯 단계가 남아 강의가 안 바뀐 것처럼 보였다.
  • 선생님께 어디까지 지울지 여쭤 "강의 내용 전부 비우기"를 고르셨다(2026-10-30). 축 여덟 단계의 내용을 다 비운다. 강의와 칸은 남는다(다시 올리면 바로 채워지게). 강의실 연결 콘텐츠, 성적, 진도도 그대로다. 오늘의 질문과 미션 활동 메뉴 이름은 다른 메뉴 소유라 둔다.
  • 고르지 않은 길 둘(기록만): 칸까지 떼기(학생 화면에서 개념 노트 카드가 사라진다), 강의 자체를 지우기(그건 활동지 지우기가 아니라 강의 삭제라 강의 라이브러리에 둘 일이다).

"강의실에 꽂다"가 아니라 "강의실 연결 콘텐츠" (135, 10-30)

  • "그 강의실에 꽂는거 라고 하지말고 강의실 연결 콘텐츠라고 해줄래?" → 화면 문구와 코드 주석, 레포 문서에서 "꽂다"를 다 걷었다. 강의 라이브러리의 탭 이름이 "강의실에 꽂기"에서 강의실 연결 콘텐츠가 됐다. 줄여 부를 때는 연결 강의, 움직임은 연결한다("강의실에 연결했습니다"), 없을 때는 연결된 강의가 없습니다다.
  • 컬렉션(course_lessons)과 함수 이름(placeLesson 등)은 그대로 둔다: 코드 식별자는 이름 규칙 밖이다.

  • 모아서 보기를 배포 주소에 올린다. "lms2027/preview로 만들어서 푸시해줘. 내가 확인 좀 하게." 주소는 https://hoseong911.github.io/lms2027/preview/. 전에 있던 tools/미리보기.html은 이 자리로 보내 주기만 한다. (101, 10-30)
