콘텐츠 구조 범용화 — 섹션, 템플릿, 테마

선생님 지시 2026-10-26(3차). 요구사항 52, 53.

왜 — 콘텐츠가 표지, Dive, 개념, 미션, 생각 다섯 칸으로 코드에 박혀 있었다. 역사 수업 한 가지에만 맞는 틀이라 선생님이 메뉴를 직접 짤 수 없었다. 파워포인트처럼 쓰고 싶다는 지시.

섹션 (slide-render.js)

  • content = { lesson, sections[] }. 섹션 종류 다섯 — cover(표지), list(번호 목록), opening(여는 질문), slides(본문), prompt(답 쓰는 질문)
  • "개념"과 "미션"은 이제 특별한 것이 아니라 slides 섹션 두 개의 이름일 뿐이다. 국어면 "작품 읽기 / 활동 / 감상", 과학이면 "원리 / 실험 / 정리"로 짜면 된다
  • 섹션마다 이름, 배지, 켜기, 순서, 삭제. 배지는 슬라이드 왼쪽 위 글자다 — 2026에는 'Dive into History', '개념 Check', '생각 Check'가 코드에 박혀 있었다
  • migrateToSections — 2026 모양으로 저장된 강의는 열 때 섹션으로 옮긴다. 수업 화면도 같다
  • SECTION_TYPES와 변환을 slide-render.js 한 곳에 뒀다. 편집기와 수업 화면이 같은 표를 읽는다
  • 학습 목표와 초성 퀴즈가 번호 목록 섹션 하나로 합쳐졌다. CSS도 .slide-objectives 하나 (.slide-chosung 삭제). 글자가 많으면 섹션 글자 배율로 줄인다

편집기 (concept-note.js, admin.html)

  • 탭도 내용도 섹션 배열에서 만든다. switchSubTab과 HTML에 박혀 있던 다섯 칸 삭제
  • ceLinesFor(target)의 target이 'concept'/'mission'에서 섹션 id로. 줄 컨테이너도 lines-<id>
  • 페이지 번호는 전체 덱에서 sectionId로 센다. 개념↔미션 동기화 코드는 탭이라 필요 없어 삭제
  • 복습(타이핑) 모드에 넣을 섹션을 섹션마다 체크. 2026에는 개념 체크로 못 박혀 있었다

템플릿 (요구사항 52의 "템플릿을 구축해 놓는다")

  • settings/lesson_templates 문서 하나. 섹션 구성만 담고 내용은 안 담는다 — 내용까지 담으면 템플릿이 강의 복사본이 되어 고칠 때 양쪽을 따라다녀야 한다
  • 기본 두 벌(기본 / 역사 수업). 새 강의 만들 때 고른다. 지금 강의 구성을 템플릿으로 저장도 된다

디자인 (요구사항 53)

  • 글꼴 항목 표(FONT_SPEC)를 섹션 종류별로 재편. 표지 / 여는 질문 / 번호 목록 / 슬라이드 / 질문 / 공통
  • **미션 전용 한 벌(m*로 시작하는 키 19개와 .slide-mission CSS)을 걷어냈다. 섹션이 몇 개든 생길 수 있어 그 방식으로는 감당이 안 된다. 섹션 글자 배율(%) 한 칸**으로 바꾸고, 배율이 걸린 섹션의 슬라이드에만 계산한 px를 인라인으로 건다
  • 디자인 테마 — 색과 글꼴 한 벌에 이름을 붙여 저장하고 불러온다(settings/concept_note_themes). 2026에는 설정 문서가 하나라 모든 강의가 같은 톤이었다
  • 버그 하나 고침 — 디자인 문서에 값이 없으면 slide-style.css의 :root 옛 기본값으로 떨어져 번호 목록 글자가 17px로 나왔다. 렌더러가 스스로 기본값(title 40, obj 70, think 80, thinkGuide 50)을 채운다

이름 — MENUS의 "생각 체크"를 "오늘의 질문"으로(선생님 확정). 미션은 아직 그대로다.

확인한 것

  • 정적 — 문법, id, import, window 노출(75개), 아이콘, CSS 클래스, 중괄호 짝, 화면 규칙, 1~3차 지시 유지. 검증 묶음 셋 전부 통과
  • 노드에서 렌더러를 실제로 돌림 — 섹션 종류, 빈 섹션, 2026 구조 변환(7섹션 9슬라이드), 배지 전달, 복습 플래그, 꺼 둔 섹션 제외, 배율 px 계산
  • 브라우저 — 임시 페이지로 섹션 강의 9장을 실제로 그려 눈으로 확인(표지, 번호 목록, 여는 질문, 행 나열, 비교표, 인용, 배율 80% 미션, 질문). 글자 크기 obj 70 / 본문 60 / 미션 48 / 제목 40. 어드민은 콘솔 오류 0건, 사이드바 5칸, 본문 폭 1680px, 필요한 전역 함수 전부 떠 있음

로컬 서버 포트 — AI 변환 프록시(claudeProxy)가 허용하는 origin 목록에 localhost는 5500만 들어 있다(hoistory functions/index.js). 로컬로 띄울 때 다른 포트를 쓰면 AI 변환이 403으로 막힌다. 활동지 업로드는 hwpx와 pdf 둘 다 되고, pdf는 파일 그대로 Claude에 넘어가 레이아웃(표, 음영, 박스)을 본다 — hwpx는 태그를 떼고 글자만 남아 표 구조가 사라진다.

확인 못 한 것 — 어드민 편집기 안쪽(섹션 추가, 탭 이동, 저장). 선생님 계정 로그인이 필요해서 못 열었다. 로그인하신 뒤 개념 노트에서 강의를 하나 만들어 봐 주셔야 한다.

개념 노트를 별도 메뉴로, 올릴 강의실은 체크와 일괄 선택, 내용 너비 확대

선생님 지시 2026-10-26(2차) 1~3번.

  • (1) 개념 노트를 사이드바 별도 메뉴로. "메뉴별 관리"는 페이지가 아니라 구분선으로 묶은 카테고리라는 지시. 메뉴를 고르는 페이지(data-page="bymenu", renderPickMenu, renderByMenuBody)를 통째로 지우고, 사이드바 가운데 묶음에 개념 노트를 한 줄로 세웠다. 미션, 생각, 성적은 만들 때 여기에 한 줄씩 더한다. 반별 관리는 그대로 — 강의실 하나를 고르고 그 강의실의 메뉴 칸을 보며, 개념 노트 칸을 누르면 같은 화면으로 간다
  • 쓰는 곳이 없어진 state.pickedMenu와 menuByKey import도 같이 뺐다
  • (2) 올릴 강의실을 체크로 고른다. 칩을 켜고 끄던 것을 진짜 체크박스 목록으로 바꿨다. 위에 과목, 학년, 반 일괄 선택 줄 세 개 — 칩 하나가 그에 맞는 강의실을 전부 켜고 끈다. 전부 켜져 있으면 칩이 켜진 것으로 보이고, 누르면 전부 끈다
  • ask()의 칸 종류 picks를 rooms로 갈아치웠다(같은 일을 두 길로 두지 않는다). options에 subject, grade, classNo를 같이 넘겨야 일괄 줄을 만들 수 있다
  • 체크 목록은 창이 좁으면 한 줄에 하나뿐이라 ask({ wide: true })와 .modal.wide(720px) 신설. 목록은 auto-fill minmax(150px,1fr) 격자
  • (3) 내용 너비. .adm-main의 max-width가 1000px이라 강의 선택 줄의 버튼들과 디자인 패널이 두 줄로 접혔다. 1680px으로 넓혔다. 강의 선택 줄은 드롭다운만 줄어들고 버튼들은 안 밀리게(flex-shrink:0, 드롭다운 flex:1 1 240px)

확인한 것 — 정적 검증 10묶음 전부 통과(문법, id 87개 유일, 편집기가 찾는 id 34개, import 이름, 인라인 노출, 아이콘, CSS 클래스, 화면 규칙, HTML 태그 짝, 공개와 강의실 연결 10가지, 2차 지시 10가지). 브라우저로는 못 봤다.

개념 노트 이식 — 콘텐츠 올리기와 디자인 조절, 올릴 강의실 고르기

  • 선생님 지시(요구사항 47) — 개념 노트로 이식하는 것은 강의 생성 기능과 학생이 볼 수 있는 기능이다. 강의 내용은 2027에서 다시 만들므로 가져오는 것은 콘텐츠 올리는 기능과 디자인 조절뿐이고, 그래서 강의를 만든 뒤 올릴 강의실을 고르는 기능을 더한다. 2027 강의실 구조에 맞게.
  • 10-25에 멈춰 있던 1단계(파일만 옮겨 두고 화면에 안 붙인 상태)를 끝내고 올릴 강의실을 함께 붙였다.

올릴 강의실 (새 기능)

  • model.js에 listLessonCourses, setLessonCourses, syncLessonRows, deleteLessonEverywhere. 강의 하나를 여러 강의실에 올릴 수 있다. 올린다 = course_lessons에 줄 하나
  • setLessonCourses는 뗄 수 있는 범위(scopeIds)를 받는다. 라이브러리 강의는 연도와 무관하게 남아서 2027 강의실과 2028 강의실에 함께 올라가 있을 수 있다. 고르기 창이 보여 준 학년도 밖의 줄까지 지우면 다른 해에서 강의가 조용히 사라진다
  • 공개 스위치는 강의 하나에 하나다(선생님 지시 유지). 켜면 올려 둔 강의실 전부가 같이 열린다. 학생 화면이 강의실 하나만 읽고 끝나도록 isOpen과 lessonNo, title을 올린 줄에도 적어 두고, 스위치를 누를 때와 저장할 때 syncLessonRows로 같이 고친다
  • 강의 삭제는 올린 줄까지 지운다. 남기면 학생 화면에 내용 없는 강의가 뜬다. 강의 라이브러리 페이지의 삭제도 같은 함수로 바꿨다(예전에는 "붙인 연결은 남습니다"였다)
  • ask()에 여러 개 고르기 칸(type:'picks') 신설. 강의실 칩을 여러 개 켜고 끈다
  • 강의를 추가하면 바로 올릴 강의실 고르기 창이 뜬다. 취소하면 올린 곳 없이 남는다

2026-10-27 (이어서) — 강의실 관리를 실제로 돌아가게

선생님 지시 "그다음부터 다시 뼈대 작업. 어드민부터"(요구사항 81)에 따라 강의실 관리부터 채웠다.

왜 여기부터인가 — 학년도를 만드는 기능이 아예 없었다. Firestore를 먼저 붙여도 데이터베이스가 비어 있으면 2027학년도를 만들 방법이 없어 첫 단추를 못 끼운다. 강의실은 다른 모든 화면의 입구이기도 하다.

만든 것

  • 학년도 만들기 — 학년도 줄 오른쪽 끝에 인라인 칸을 붙였다(팝업 안 띄움). catline()에 extra 인자를 더해 줄 끝에 붙인다. 2000~2199 범위와 중복을 막는다. 만들면 그 학년도로 바로 옮겨 간다. 학년도가 하나도 없으면 "학년도가 없습니다"만 보인다
  • 강의실 수정 — 연필을 누르면 그 줄이 그 자리에서 입력 칸이 된다(요구사항 66의 인라인 방식). 저장은 체크, 취소는 x. 화면을 떠나거나 학년도를 바꾸면 수정 상태가 풀린다
  • 강의실 삭제 — 확인 창에서 강의실 이름("사회 301")을 그대로 쳐야 버튼이 켜진다(화면 규칙 2026-10-25). 무엇이 같이 없어지는지 실제 숫자로 보여 준다(학생 n명, 꽂힌 강의 n개, 걸린 복습 n개). 강의 내용 자체는 창고(lessons)에 남는다는 것도 적는다
  • 중복 막기 — 같은 학년도에 과목, 학년, 반이 똑같은 강의실은 못 만든다. 수정할 때도 검사한다
  • 확인 창(confirmDelete) — 새 뼈대에는 모달이 아예 없었다. 브라우저 기본 confirm을 쓰지 않는 코드 규칙 때문에 하나 만들었다. Esc로 닫고 Enter로 확인, 바깥을 눌러도 닫힌다
  • 엔터로 보내기 — 인라인 폼 칸에서 엔터를 치면 그 줄의 주 버튼(.btn-text 또는 .ib-primary)을 누른 것으로 본다. 줄마다 핸들러를 달지 않는다
  • model.js에 addYear, updateCourse, deleteCourse, courseDeps 추가. 삭제는 course_ 접두가 붙은 것만 지우고 창고는 안 건드린다(명단, 꽂힌 강의, 걸린 복습, 성적)

안 만든 것과 그 이유

학년도 삭제는 넣지 않았다. 요구사항 19가 "이름 입력 대신 관리자 메일과 비밀번호로 재인증"을 못박았는데, 지금은 Firebase Auth를 아예 안 붙인 상태다. 이름을 치는 확인으로 임시로 만들면 선생님이 "너무 허술하다"고 물린 바로 그 방식을 다시 내놓는 꼴이라 만들지 않았다. Firestore와 Auth를 붙일 때 같이 만든다.

  • 메뉴별 — 개념노트, 미션, 질문노트, 형성평가, 복습, 성적 여섯 칸. 하나를 고르면 그 칸만 강의 순서대로 모여 나온다(1강 붕당의 형성과 전개, 2강 예송논쟁의 쟁점). 2026 hoistory lms의 메뉴와 같은 방식이다

화면 상태가 view 하나에서 view + layout + menuKey로 늘었다. login / rooms / home / lesson / menu / part 여섯 화면이다.

  • 노치 대응(env(safe-area-inset-*))

4) 강의 슬라이드는 늘 새 탭 전체화면 (87) — slide.html 새로

개념노트 칸에서 펼치지 않고 슬라이드 열기 버튼 하나만 둔다. 누르면 새 탭이 뜬다.

  • 위쪽 막대는 평소 숨고 마우스를 올리거나 화면 위를 건드리면 나온다. 투사 중에 안 거슬리게
  • 전체화면은 버튼을 눌러야 들어간다 — 브라우저가 자동 진입을 막는다. 전체화면에 들어간 뒤에만 screen.orientation.lock('landscape')이 먹어서 모바일 가로가 된다
  • 좌우 화살표, 스페이스, F(전체화면) 키로 조작
  • 아직 뼈대다 — 쪽 내용이 없어 표지 한 장만 선다. 슬라이드 엔진은 방학 과제이고 slide-render.js, page-lesson.*이 그때 쓸 재료다
